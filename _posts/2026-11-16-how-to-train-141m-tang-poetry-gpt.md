## 引子：为什么还要从零炼一只 141 万参数的模型？

在前面的文章里，我们聊过 RoPE 怎么把旋转几何塞进注意力，也聊过 FFN 如何在高维空间里“先把一件事展开，再把它收起来”。

原理读得再透彻，终究是看别人盖好的高楼。总会有那么一个冲动：**能不能找一块最小的空地，从挖第一铲土开始，亲手把整套当代大语言模型的流程跑一遍？**

不是微调一个现成的 7B 开源权重，也不是调用几行高层 API，而是真正从零开始：
- 先写一个不依赖 PyTorch 的纯 Python 标量求导引擎，看懂梯度怎么顺着计算图流回来；
- 再把底座切到 PyTorch，倒进两万多首全唐诗，亲手装上 **RMSNorm、RoPE、QK-Norm、SwiGLU、Sequence Packing**；
- 接着走完后训练三步曲：**SFT 指令微调 → 可验证规则奖励的 GRPO 强化学习 → 口语化对话 SFT 与词表热扩**。

最终炼出来的，是一只只有 **141 万参数（准确数字是 `1,415,424`）** 的微型“小诗人”。

它当然写不出李白杜甫的千古绝唱，但已经能听懂大白话、按指定体裁和题目作诗、写藏头诗，甚至顺着名句往下续写。下面是这只最终训完的模型在不同提示词下的几段真实输出：

> **输入**：`写一首关于秋夜的五言绝句`
> 夜雨临江水，秋风起客心。
> 明朝独自醉，明月照孤林。

> **输入**：`来首七言绝句，主题是送别`
> 江皋日暮不成还，野径青山何处闲。
> 欲别故人多不得，不知秋草与寒山。

> **输入**：`用“风花雪月”作一首藏头诗`
> **风**吹玉笛愁，**花**落雁城头。
> **雪**落金陵路，**月**明玉树楼。

> **输入**：`续写：海上生明月，`
> 云间见白头。
> 今宵闻海鹤，相见有风流。
> 落日临江上，孤云上桂楼。
> 孤舟如不见，惆怅望君愁。

这篇文章，就是记录这只“141 万参数小诗人”如何一步步长大成人的全过程。项目的完整训练代码、数据分片与最终模型权重已经开源在 GitHub 仓库：[yangzc2004-bit/tang-poetry-gpt](https://github.com/yangzc2004-bit/tang-poetry-gpt)。

## 一、起手式：4,192 个参数与 75 行纯 Python 的祛魅（`my_gpt`）

一切的起点，是 Andrej Karpathy 的 **microgpt** 项目。它的核心理念非常迷人：把所有工程优化、分布式框架、GPU 加速全剥掉，只保留 GPT 最赤裸的数学骨架。

在真正碰唐诗之前，我先照着这套极简思路写了一个纯 Python、零第三方依赖的 `my_gpt`：

1. **75 行手写标量自动求导引擎**：定义一个只包裹单个浮点数的 `Value` 类，记录每个节点的父节点 `_children` 和局部导数 `_local_grads`。一次前向传播把加法、乘法、指数、对数、ReLU 串成有向无环图，调用 `.backward()` 时再按拓扑逆序把链式法则乘回去。
2. **最小的 GPT 骨架**：只有 `1` 层、`16` 维隐状态、`4` 个注意力头、`16` 的上下文窗口，词表只有 `27` 个 token（26 个英文字母 + `<BOS>`），总计 **`4,192` 个参数**。
3. **数据集**：Karpathy 在 `makemore` 里用过的英文人名列表 `names.txt`。

纯 Python 标量计算图慢得像老牛拉车，但跑完 `1000` 步之后，这个只有四千多个参数的小东西居然真的学会了英文人名的拼写规律，张口就能“编”出像模像样的新名字：

```text
sample  1: salia
sample  2: jaon
sample  3: atilia
sample  4: karen
sample  5: janan
sample  6: dielan
sample  7: alann
sample  8: taran
```

这一步没有追求任何性能指标，它只做了一件至关重要的事：**祛魅**。

当你亲眼看着几千个标量 `Value` 靠加减乘除和拓扑排序完成梯度回传、并从一团高斯噪声里长出音节感的时候，大模型就不再是黑盒里的魔法，而是一台构造清晰、完全可以被拆解和改造的机器。

## 二、迁移战场：2.5 万首全唐诗与现代 GPT 底座打磨（`poetry_gpt`）

摸清原理后，是时候换上 PyTorch 向量化引擎，把战场从“英文名字”搬到“全唐诗”了。

![从标量自动求导计算图演进到 141 万参数现代 GPT 架构的示意图]({{ '/assets/images/posts/poetry-gpt-micro-to-modern.svg' | relative_url }})
<p class="figure-caption">从左边 75 行纯 Python 标量计算图出发，经过向量化重构，长成右侧具备 RoPE 旋转位置编码、QK-Norm 与 SwiGLU 门控的 4 层现代 GPT。</p>

### 1. 数据清洗与字符级分词

语料来自开源项目 `chinese-poetry` 的全唐诗分片。我拉取了前 `25` 个分片（`poet.tang.0.json` 到 `poet.tang.24000.json`，共 25,000 条原始记录），做了一套克制的清洗流水线：

- 去掉诗题和正文里的括号注释（如校注、异文说明）与空白字符，统一繁转简；
- 剔除含英文字母、数字或残缺方框符号 `□` 的脏记录；
- 考虑到小模型的窗口只有 `128` 个 token（还要给后面的指令 Prompt 留出约 `34` 个字符的位置），只保留正文长度在 `12` 到 `94` 字之间的诗作。

最终筛选出 **`20,453` 首**干净的全唐诗（其中 5% 划为验证集）。

分词器没有上 BPE，而是直接用了**字符级（Character-level）分词**。原因很直观：在古诗场景下，汉字本身就是天然的语义和音步单位——五言一句就是 5 个 token，七言一句就是 7 个 token，数错一个字都不会被子词切分掩盖掉。通过设置最小字频 `min_char_freq = 3` 过滤掉极生僻字后，底座词表定格在 **`4,748` 个字符**。

### 2. 把现代大模型的积木一件件装上去

模型整体保持轻巧克制的体量：**4 层 Transformer Block、4 个注意力头、128 维隐状态（`head_dim = 32`）、`block_size = 128`**，并且让输入词嵌入 `wte` 与输出投影 `lm_head` **共享权重（Weight Tying）**——在词表有近五千字而隐维度只有 128 的情况下，这一步直接省掉了一整块 `4748 × 128`（约 60 万）的冗余参数。

围绕这套骨架，我陆续做了几轮结构升级和对比实验（早期先在一版 `3,679` 词表上做结构消融，定型后再切到 `4,748` 词表长训）：

1. **用 RoPE 取代可学习绝对位置编码**：在早期的 `3,679` 词表对比中，把 `LearnedPositionalEmbedding` 换成旋转位置编码 RoPE 后，验证集 Loss 从 `4.3810` 降到了 `4.3147`。古诗天然强依赖相对距离（比如每隔 5 字或 7 字出现一次逗号、句号），RoPE 让注意力在计算相对偏移时省力很多。
2. **Pre-RMSNorm + QK-Norm + SwiGLU**：把 LayerNorm 换成去掉均值中心化和偏置的 `RMSNorm`，并在注意力打点积前额外对 $Q$ 和 $K$ 做一次 `RMSNorm`（QK-Norm）防止注意力分数爆炸；MLP 层也从传统激活升级为当今主流大模型常用的门控结构 **SwiGLU**。
3. **两条探索支线：MoE 与 Muon 优化器**：
   - **稀疏 MoE**：我试过把每层的 MLP 换成 `8` 个缩小版 SwiGLU 专家、每次激活 `Top-2`，并加上均衡负载的辅助损失（Switch/Mixtral 公式），验证 Loss 在 `4.3168`，和同 FLOPs 稠密 SwiGLU（`4.3159`）几乎打平，但路由器和多专家在 100 万级小模型上引入了额外碎片化，最终还是回归了更紧凑的稠密 SwiGLU。
   - **Muon 优化器**：我还专门实现了一版 `MuonWithAuxAdam`——对 Transformer Block 里的 2D 权重矩阵用 5 步 Newton-Schulz 迭代做正交化更新，Embedding 和 1D Norm 仍用 AdamW。小模型上它的收敛也很稳（`4.3305`），不过在后续 SFT 和短步数微调中，常规 AdamW 的超参更省心，因此主线仍统一采用 AdamW。

### 3. 训练效率的关键一招：Sequence Packing 与文档隔离掩码

写唐诗模型最容易踩的坑是**算力全浪费在 `<PAD>` 上**。

一首五言绝句连带标点才 24 个字，而上下文窗口 `block_size = 128`。如果一首诗占一行、剩下 100 个位置全填 `<PAD>`，超过 80% 的矩阵乘法都在算空气。

于是我实现了一个 **First-Fit Sequence Packing**：把多首短诗首尾拼接进同一条 `128` 长度的序列里。但这会带来一个致命问题——**下一首诗会不会偷看上一首诗的内容？**

![Naive Padding 与 Sequence Packing 加上文档隔离掩码的对比示意图]({{ '/assets/images/posts/poetry-gpt-packing-mask.svg' | relative_url }})
<p class="figure-caption">通过 First-Fit 序列打包消灭约 80% 的空转填充，并用分块下三角掩码与按首归零的位置索引防止不同唐诗之间相互串台。</p>

解决办法是在 `forward` 里同时传入每个 token 所属的诗编号 `doc_ids` 和重置后的位置编号 `pos_ids`：
- **注意力层**：用 `same_doc & causal` 构造分块下三角文档隔离掩码（`_build_doc_causal_mask`），强行切断不同诗之间的注意力连线；
- **位置编码层**：每当一首新诗开始，`pos_ids` 从 `0` 重新计数，确保 RoPE 不会把第二首诗的第一个字误认成第 30 个位置。

加上 Packing 和扩充后的 `4,748` 词表，跑完 `2,500` 步预训练后，底座模型 `poetry_gpt_base.pt` 的最优验证集 Loss 稳定降到了 **`4.0964`**（第 2250 步）。

此时如果直接让 Base 模型自由续写，它已经能顺畅地吐出唐诗的韵律和意象了：

> **Base 模型自由生成（无提示词，仅输入 `<BOS>`）**：
> 自从青史去，今日白头期。
> 旧宅无人住，新安住汝时。
> 野人唯有客，山鸟未能还。
> 莫怪春风事，无人独自期。

但它还只会“闷头写自己的”，你没法让它按你的题目、体裁或藏头要求来写。这就要进入后训练了。

## 三、后训练三步曲：从“会接字”到“听懂人话、守住格律”

整条训练流水线在后训练阶段走了三个清晰的台阶：

```text
Pretrain (poetry_gpt_base.pt, val_loss=4.0964)
   │  20,453 首全唐诗 + RoPE / QK-Norm / SwiGLU / Sequence Packing
   ▼
Stage 2: SFT (poetry_gpt_sft.pt, val_loss=3.9857)
   │  5 类结构化指令 + Prompt Loss Masking (-100)
   ▼
Stage 3: GRPO (poetry_gpt_grpo.pt)
   │  可验证规则裁判 (G=8 组内对比 + KL=0.04)，格式合规率 71.4% -> 100.0%
   ▼
Stage 4: Chat-SFT (poetry_gpt_chat_sft.pt, val_loss=3.7180, 1,415,424 params)
      Embedding 热扩表 (4748 -> 4775) + 寒暄种子与口语模板池
```

### 1. Stage 2 — SFT 指令微调：只学怎么答，不学怎么问

为了让底座学会听指令，我自动把每首唐诗改写成了最多 **5 类指令-回答对**：
1. **体裁 + 题目**：`体裁：五言绝句｜题目：秋夜`
2. **仅指定体裁**：`体裁：七言绝句`
3. **仅指定题目**：`题目：春晓`
4. **藏头诗**：自动提取原诗每句首字，生成 `藏头：XXXX`
5. **首句续写**：拆出第一句，让模型接着往下写 `续写：...`

这步在 `sft_dataset.py` 里共构造出了 **`84,366` 条训练指令对**（经 Sequence Packing 打包成 `41,596` 条定长样本）。其中最核心的细节是 **Loss Masking**：用 `<USER>指令<BOT>诗作<EOS>` 拼接输入，但在计算交叉熵损失时，把 `<USER>指令<BOT>` 对应的目标全部掩码为 `-100`（只对回答部分占 `76.5%` 的 token 算梯度），并且把学习率降到预训练的五分之一（`2e-4`），避免把底座好不容易攒出来的古典语感冲散。

训练 `1,200` 步后，验证集 Loss 降到了 `3.9857`。模型终于学会了“看菜下饭”——给它 `体裁：五言绝句｜题目：秋夜`，它能写出：

> 晓入寒江半，秋生夜月长。
> 唯当竹阴里，无处到溪边。

### 2. Stage 3 — GRPO 强化学习：写一个不靠人类的“古诗格律裁判”

SFT 之后，我很快发现了小模型的一个典型毛病：**语感有了，但规矩不够稳**。

我拿 `28` 道未见过的固定考题（包含 16 道合成四字藏头题，如“春夏秋冬”、“风花雪月”，和 12 道常见名题体裁题）测了一下 SFT 模型：
- **体裁格式完全合规率（`format_ok`）只有 `71.4%`**——五言绝句偶尔会写出六个字，或者多写一行；
- **合成四字藏头全中率（`acrostic_hit`）只有 `12.5%`**——因为它以前没见过这种字面组合，容易写着写着就忘了第四个字该用什么开头。

怎么把格式规矩强行掰回来？古诗格律其实是一种天然的 **可验证规则（Verifiable Reward）**——不需要人类标注员打分，也不需要再训一个 Reward Model，几十行正则表达式和计数逻辑就能当铁面裁判（`grpo_reward.py`）：
- 句数对不对（绝句 4 句、律诗 8 句）、每句字数对不对（五言 5 字、七言 7 字）；
- 标点是不是标准的“逗号结尾 + 句号收尾”对联行结构；
- 藏头诗每一句的第一个字是否精准命中目标字；
- 再加上连续叠字复读惩罚，防止模型靠无脑重复高分字作弊。

![GRPO 组内相对策略优化与古诗规则裁判图解]({{ '/assets/images/posts/poetry-gpt-grpo-judge.svg' | relative_url }})
<p class="figure-caption">GRPO 的核心机制：同题采样 8 首候选诗，由规则裁判打分并做组内优势归一化，再借助 KL 散度拴住模型不偏离 SFT 原有的诗意语感。</p>

训练算法选了 **GRPO（Group Relative Policy Optimization）**——它省去了 PPO 里占显存又难训的 Critic 价值网络，做法非常直觉：
1. 每步抽取 `4` 道题，对同一道题用较高温度（`temperature = 0.9`）一口气采样 **`G = 8` 首候选诗**；
2. 裁判给这 8 首诗打分后，直接在组内做均值方差归一化，算出相对优势 $A_i = \frac{r_i - \bar{r}}{\text{std}(r) + \epsilon}$——**比同组平均水平好的写法就鼓励，差的就压制**；
3. 同时拉着一份冻结的 SFT 参考模型副本计算 **KL 散度惩罚**（$\beta = 0.04$），像一根绳子一样拴住策略模型，防止它为了刷高格式分而开始胡言乱语。

而且为了让藏头能力真正泛化，题库里特意混入了 **`3,000` 道随机拼出来的合成四字藏头题**。

跑完 `300` 步 GRPO 后，在同一套 `28` 道验证题上再测一次：
- 平均奖励从 `0.9776` 升到了 **`1.4107`**；
- **体裁格式合规率直接从 `71.4%` 拉满到了 `100.0%`！**

看看前后变化很明显——比如同样是 `藏头：春夏秋冬`，SFT 阶段（seed=7）一不小心刹不住车写成了十二句长排律，而 GRPO 阶段（seed=7）稳稳收在了标准的五言四句，并且字数标点严丝合缝。不过实话实说，在单次低温度采样下，未见过的四字藏头“四字全中率”依然受限于 141 万的脑容量（测试集单次评估为 `6.25%`），但格律节奏和收尾意识已经脱胎换骨。

### 3. Stage 4 — 口语化 SFT 与词表热扩（`chat_sft.py`）

到了这里，模型已经很会按 `体裁：五言绝句｜题目：秋夜` 这种“八股文提示词”写诗了。但真正和人对话时，谁会这么说话？大家只会打：
- “你好呀” / “你是谁”
- “帮我写一首关于秋夜的五言绝句”
- “用‘风花雪月’作一首藏头诗”

这里立刻撞上了两个工程难题：
1. **指令太死板**：没见过大白话提问；
2. **词表缺字**：全唐诗里极少出现甚至根本没有“你、帮、吗、藏、续、呢、呀”这些现代口语字，直接编码会全部丢字（OOV）。

如果因为缺二十几个字就推翻底座从头重训，性价比太低。于是我在 **GRPO 模型** 的基础上做了一次 **词表热扩 + 口语化 SFT**：

- **Embedding 动态热扩表**：扫一遍口语模板与寒暄语料，收集出全唐诗词表里缺失的字符以及 `<USER>` / `<BOT>` 对话标记，把词表从 `4,748` 热扩到 **`4,775`**（`+27` 个新 token，总参数量定格在 **`1,415,424`**）。原有的 `4,748` 行 Embedding 权重原封不动复制过来，只用小高斯噪声初始化新增的 27 行，同时因为权重共享，输出层 `lm_head` 也自动同步扩容。
- **口语同义模板池 + 种子寒暄过采样**：把原本的 5 类任务扩写成数十种大白话问法（再加上“随便写一首诗”自由创作），并手写了 `20` 组打招呼、自我介绍和使用说明的种子对话，以高重复度混入 **`102,019` 条训练对**（打包成 `50,894` 行）里一起训练 `2,000` 步。

最终，`poetry_gpt_chat_sft.pt` 的验证集 Loss 进一步降到了 **`3.7180`**，这只 141 万参数的小诗人正式毕业。

## 四、验收与复盘：141 万参数的“能力边界”在哪里？

把这四个阶段串起来回看同一道题（`关于秋夜的五言绝句`），能非常清晰地看见每一步训练刻在权重里的痕迹：

| 阶段 | Checkpoint | 输入方式 | 真实生成样例 | 变化解读 |
| :--- | :--- | :--- | :--- | :--- |
| **Base** | `poetry_gpt_base.pt` | `<BOS>` 自由续写 | `自从青史去，今日白头期。`<br>`旧宅无人住，新安住汝时。...` | 懂唐诗韵味与对句，但完全不听指令、随机起题 |
| **SFT** | `poetry_gpt_sft.pt` | `体裁：五言绝句｜题目：秋夜` | `晓入寒江半，秋生夜月长。`<br>`唯当竹阴里，无处到溪边。` | 开始理解“秋/夜”意象与五言四句，但长复杂约束容易失控 |
| **GRPO** | `poetry_gpt_grpo.pt` | `体裁：五言绝句｜题目：秋夜` | `晓入寒山外，秋风长不行。`<br>`落花开古巷，无酒到闲情。` | 格式规则被强力拉齐（验证集格式合规率 71.4% → 100%） |
| **Chat-SFT** | `poetry_gpt_chat_sft.pt` | `写一首关于秋夜的五言绝句` | `夜雨临江水，秋风起客心。`<br>`明朝独自醉，明月照孤林。` | 听懂了现代口语里的主题与体裁，意象连贯且格律押韵 |

当然，诚实地记录它的短板和赞美它的亮点同样重要。跑过大量样例之后，**141 万参数的物理天花板**非常清晰：

1. **它擅长什么**：
   - 极短时间内（纯单机训练）就能把五言/七言的字数节奏、标点结构、常见古典意象组合（秋风、孤楼、白发、明月、江南）吃得很透；
   - 通过 **Prompt Masking + GRPO 可验证奖励 + 热扩词表**，即使只有 1.4M 参数，依然能够完整跑通指令遵循、规则对齐和口语理解，不再只是“文本续写器”。
2. **它还不擅长什么**：
   - **长白话容易嘴瓢**：因为它 99% 的“人生阅历”都是全唐诗，面对“你是谁”这种现代散文对话时，有时能完整答出“我是杨少侠写字板里的唐诗小助手，基于自研微型GPT训练”，但多说几个字就容易陷入局部复读；
   - **硬约束（如四字藏头）依赖采样运气**：能写出四字全中又颇有意境的绝句（前面展示的“风花雪月”就是真实采样命中的），但并不能保证每次采样都百发百中；
   - **没有真正的平仄声调知识**：字符级分词加小参数量，学会的是“看起来像格律诗”的字词搭配与句法对仗，离真正的平水韵和深层立意还差得很远。

但正因为如此，这个项目才格外让人着迷——你亲手把 75 行纯 Python 计算图一点点搭成了拥有现代 Transformer 架构、经历过 SFT 与强化学习洗礼的 141 万参数生命体。在算力动辄千卡万卡的今天，**用笔记本就能把当代 LLM 的核心方法论摸得清清楚楚，本身就是一件浪漫到骨子里的事。**
