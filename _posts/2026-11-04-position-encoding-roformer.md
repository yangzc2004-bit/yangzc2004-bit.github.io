读《Attention Is All You Need》时，最容易被忽略、却又最基础的问题是：自注意力明明在处理一个序列，它怎么知道谁先谁后？

答案并不在注意力公式本身，而在额外加入的位置信息。从原论文的正弦位置编码，到后来强调相对位置的方法，再到 RoFormer 使用的 RoPE，这条路线其实是在不断回答同一个问题：**怎样让位置关系更自然地进入注意力计算？**

这篇文章会先建立整体图景，再讨论公式背后的设计取舍。至于 RoPE 更细的二维旋转、复数形式和代码实现，我还会在另一篇笔记里单独展开。

## 序列不是词的集合

假设我们有两句话：

> 猫追狗。

> 狗追猫。

两句话包含完全相同的词，但语义相反。人依靠词序判断谁发出动作、谁承受动作，而只处理内容的模型看不到这层关系。

这就是序列建模和集合建模的差别。集合只关心有哪些元素，序列还关心元素如何排列。排列不仅改变阅读顺序，也会改变指代、语法、因果和计算依赖。

在代码中，这种区别更加直接：`a = b + 1; b = 2` 与 `b = 2; a = b + 1` 不是同一个程序。在时间序列中，交换昨天的数据和今天的数据，也会破坏趋势与周期。

所以，位置不是为了让模型多记一个编号，而是因为顺序本身参与了意义。

## 裸自注意力看不到原始顺序

把注意力暂时看成一个根据内容匹配信息的机制。对于输入矩阵 $X$，它计算：

$$Q=XW_Q,\quad K=XW_K,\quad V=XW_V$$

$$\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

这里没有任何一项专门记录“第几个词”。

如果用置换矩阵 $P$ 打乱输入行，那么 $Q$、$K$、$V$ 的行也会按相同方式重排。softmax 同样逐行计算，最终结果只是输出的行被重排：

$$\operatorname{Attention}(PX)=P\operatorname{Attention}(X)$$

也就是说，输入换顺序，输出跟着换顺序，但模型并没有因此理解原始顺序。这叫置换等变。

为了让这个结论足够干净，我们暂时不讨论因果掩码、特殊位置偏置等额外结构。因果掩码本身就含有顺序约束，不能拿来证明裸注意力完全不含位置信息。

## 位置编码到底要提供什么

一种理想的位置表示，至少需要考虑下面几件事。

**可区分。** 不同位置不能完全相同，否则模型仍然无法知道当前词在哪里。

**有结构。** 相邻位置、间隔很远的位置应当存在某种可学习的规律，而不是一堆毫无关系的随机向量。

**能进入后续计算。** 表示再漂亮，如果经过第一层后就被冲淡，也无法帮助注意力建模关系。

**适应目标长度。** 固定位置表使用简单，但超出表长的位置如何处理，需要额外设计；函数式表示则更自然地生成新位置。

这些要求之间没有绝对胜负。可学习位置嵌入和正弦位置编码，就是在这些约束下做出的不同选择。

## 正弦位置编码：给每个位置一组波形

原论文使用不同频率的正弦和余弦函数：

$$PE_{(pos,2i)}=\sin\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right)$$

$$PE_{(pos,2i+1)}=\cos\left(\frac{pos}{10000^{2i/d_{\text{model}}}}\right)$$

先不用把它当成一条需要背诵的公式。可以把它想象成一组转速不同的时钟：有的指针转得快，用来区分邻近位置；有的转得慢，用来标记较大的跨度。每个位置都对应这些时钟的一组读数。

偶数维度和奇数维度成对出现，因此每组读数实际上是一个二维平面上的点：

$$\left(\sin(pos\theta_i),\cos(pos\theta_i)\right)$$

随着 $pos$ 增加，这个点沿单位圆移动。不同组的角速度不同，于是高维位置编码同时包含许多尺度。

这与数字编码也有一点相似。十进制数的个位变化快，十位变化慢；正弦编码则把离散进位换成连续周期。两者都在用不同尺度共同表示一个位置。

## 为什么正弦和余弦要成对出现

只看正弦会损失一部分方向信息。例如，$\sin x$ 在某些不同位置上可能得到相同的值；同时提供正弦和余弦，就能确定单位圆上的具体角度。

成对出现还带来一个方便的代数性质。根据和差公式：

$$\sin(a+b)=\sin a\cos b+\cos a\sin b$$

$$\cos(a+b)=\cos a\cos b-\sin a\sin b$$

所以，位置 $pos+k$ 的编码可以由位置 $pos$ 的编码经过线性变换得到：

$$PE_{pos+k}=M_kPE_{pos}$$

其中 $M_k$ 由 $k$ 决定，不需要重新查询一张新表。

但要注意一个常见误读：这个性质说明位置编码之间存在规律，不等于后面的注意力层会自动、精确地计算相对距离。网络仍要通过训练学习如何利用这些特征。数学上“可以利用”和训练后“已经学会”是两回事。

## 为什么直接加到词向量上

正弦位置编码和词嵌入维度相同，因此原论文采用相加：

$$x_{\text{input}}=x_{\text{token}}+PE_{pos}$$

这样做不会改变输入宽度，也不会改变后续线性层的接口。词嵌入负责内容，位置编码负责坐标，两者在同一份特征中叠加。

加法也不是唯一选择。可以拼接，再经过线性层压缩；也可以使用门控、调制或其他融合方式。只是相加足够简单，而且不引入额外参数。

有人担心相加会把词向量“污染”。这种担心有一定直觉基础，因为位置信息确实进入了内容通道；但神经网络本来就在学习混合特征。只要训练有效，后续层可以学会分别利用内容与位置。

真正需要记住的是：相加只是把位置送进模型，并不规定注意力必须怎样使用它。

## 可学习位置嵌入与正弦编码

如果给每个位置分配一个可训练向量，模型可以从数据中自由学习位置特征。这种方式灵活，也容易与具体任务配合。

正弦编码则由固定函数生成，不需要训练位置参数，并且能自然生成未见过的新位置。

两者可以粗略这样比较：

| 维度 | 正弦位置编码 | 可学习位置嵌入 |
| --- | --- | --- |
| 参数 | 固定函数，无位置表参数 | 每个位置都有可训练向量 |
| 新位置 | 可以直接计算 | 超出表长需要额外处理 |
| 灵活性 | 结构固定、规律明确 | 可完全依赖数据学习 |
| 直觉 | 多频波形与周期 | 每个位置的一组学习特征 |

实际模型还会受训练目标、数据规模和上下文长度影响，不能仅凭这张表判断哪种方法在所有任务上更好。

## 从绝对位置走向相对位置

绝对位置回答“这个词在第几个位置”，相对位置回答“这两个词相隔多远”。

语言中很多关系更依赖相对距离。例如，一个代词通常需要寻找前面不远的指代对象；代码里的变量引用也经常与一定范围内的定义相关。绝对编号会随段落整体移动，相对结构却可能保持不变。

在自注意力中，真正直接发生交互的是 Query 和 Key。于是问题可以进一步收紧：

> 能不能让位置 $m$ 的 Query 与位置 $n$ 的 Key 在计算匹配分数时，自然地包含 $n-m$？

这不是说绝对位置没有价值，而是希望相对关系更接近注意力计算的核心，而不是只停留在输入特征里。

RoPE 给出的办法很巧妙：不再把位置向量加到词嵌入上，而是根据位置旋转 Query 和 Key。

## RoPE：把位置变成旋转角

先只看二维向量。位置 $m$ 对应的旋转矩阵是：

$$R(m\theta)=
\begin{pmatrix}
\cos m\theta & -\sin m\theta\\
\sin m\theta & \cos m\theta
\end{pmatrix}$$

对 Query 和 Key 分别旋转：

$$q_m=R(m\theta)q,\qquad k_n=R(n\theta)k$$

它们的点积变成：

$$q_m^Tk_n=q^TR(m\theta)^TR(n\theta)k$$

旋转矩阵满足 $R(a)^T=R(-a)$，并且连续旋转的角度可以相加，因此：

$$R(m\theta)^TR(n\theta)=R((n-m)\theta)$$

最终得到：

$$q_m^Tk_n=q^TR((n-m)\theta)k$$

绝对位置 $m$ 和 $n$ 不再分别留在结果里，剩下的只有相对距离 $n-m$。这就是 RoPE 最核心、也最漂亮的地方：**编码时使用绝对位置，点积时自然呈现相对位置。**

高维向量则按两个维度一组，每一组以不同频率旋转。这样既保留高频的局部区分，也保留低频的大范围位置变化。

## 一个只关心相对位移的小例子

假设某组二维 Query 和 Key 都指向横轴正方向，位置分别为 $m=3$ 和 $n=5$。旋转后，二者方向夹角与 $3$、$5$ 各自是多少无关的一部分被消去，只留下 $2\theta$。

如果把整段序列向后移动 100 个位置，变成 $m=103$、$n=105$，两者的点积仍然只包含 $2\theta$。

这正是相对位置性质的直观意义：整体平移不改变这对 token 的相互关系。

当然，真实模型中的 Query 和 Key 来自不同内容、不同注意力头，角度和长度都会变化。这个例子只用于看清位置项，不代表真实注意力只由位置决定。

## RoFormer 是什么

RoFormer 可以理解为采用 RoPE 的 Transformer 模型。RoPE 是位置编码方法，RoFormer 是把它应用到模型中的结果，两者不是同一个概念。

从计算流程上看，关键变化发生在注意力内部：先得到 $Q$ 和 $K$，再按各自位置旋转，最后计算注意力分数。

多头场景中，不同头可以分别学习关注不同关系。RoPE 为每个头提供相同的位置旋转规则，但每个头的内容投影不同，因此一个头可以偏向局部语法，另一个头也可以利用更远距离的联系。

它不需要额外维护一张随最大长度增长的位置嵌入表。不过，旋转需要为位置准备正弦和余弦值，并与具体张量布局、精度设置配合。

## 实现时真正容易出问题的地方

公式写对只是第一步。工程实现里常见的错误往往更朴素。

**维度配对不一致。** 有的实现把第 0、1 维配成一组，有的把前半维和后半维配成一组。两种布局都可以，但旋转、缓存和权重加载必须使用同一种约定。

**Query 与 Key 的位置不同步。** 解码缓存存在时，当前 token 的绝对位置不是从 0 重新开始，而应与缓存长度对应。如果把位置重置，历史与当前token的相对关系就会错误。

**缓存的 dtype 不一致。** 低精度计算中，正弦和余弦缓存的精度、设备与数据类型需要匹配。否则可能出现隐式转换、额外开销或数值差异。

**把 RoPE 错加到 Value 上。** 相对位置推导针对的是 Query–Key 点积。Value 不需要按照同样方式旋转，随意扩展会改变信息聚合的含义。

这些问题都说明：理解公式之后，还需要确认它在训练、推理和缓存路径中始终表达同一个位置约定。

## RoPE 与长度外推

“可以处理新长度”不等于“随意外推都可靠”。这是 RoPE 讨论中非常重要的边界。

函数当然可以为训练时没出现过的位置计算角度，但模型在训练中学到的内容模式、频率响应和注意力分布，可能只在一定长度范围内有效。超出后，旋转仍然合法，模型行为却未必可靠。

因此，需要区分三个层次：

1. **表示可计算**：新位置能够生成正弦和余弦值；
2. **结构不报错**：矩阵形状和缓存可以继续运行；
3. **模型仍然理解**：长距离依赖在任务上保持有效。

只有前两者成立，并不能自动推出第三者。长度外推通常需要训练策略、频率调整或专门方法来配合。

## 把这条路线放在一起看

| 方法 | 位置进入模型的位置 | 主要视角 | 需要特别理解的地方 |
| --- | --- | --- | --- |
| 正弦位置编码 | 加到输入词嵌入 | 用多频波形标记绝对位置 | 平移有规律，但不自动等于相对注意力 |
| 可学习位置嵌入 | 加入可训练的位置表 | 从数据中学习每个位置 | 表长和泛化方式需要设计 |
| RoPE | 旋转 Query 和 Key | 让点积自然包含相对位置 | 配对、缓存位置与长度外推仍有边界 |

这三种方法并不是简单的“旧方法错误，新方法正确”。它们是在不同约束下做出的设计：实现是否简单、长度是否固定、相对关系是否直接、是否需要学习额外参数。

更重要的是，它们提醒我们不要把位置编码当成论文末尾的一段附属公式。它决定了顺序信息从哪扇门进入模型，也影响后续结构能够怎样利用顺序。

## 位置表示也需要和训练目标一起理解

讨论位置编码时，很容易把模块单独拿出来比较，好像存在一种脱离任务的“最佳位置”。但位置是否有效，最终取决于模型需要从数据中学到什么。

在机器翻译中，词序和局部语法非常关键；在代码中，定义、引用和括号嵌套会形成不同尺度的依赖；在时间序列中，周期和时间间隔又可能比普通文本更重要。相同的位置表示进入不同任务后，训练信号会塑造出不同的使用方式。

因此，论文中的结构优势应该被理解为一种归纳偏置：它让某些关系更容易表达和学习，而不是替模型预先写好答案。归纳偏置越符合任务结构，通常越有机会提高数据效率；如果任务关系与这种偏置不一致，也可能需要其他机制补充。

这也解释了为什么阅读位置编码论文时，不能只看公式是否漂亮，还要看实验任务究竟需要哪些位置关系。

## 相对位置不是对所有问题的统一答案

相对位置很重要，但绝对位置同样可能有用。

如果文章标题出现在固定区域、代码文件存在固定结构，或者输入由多个有明确边界的片段组成，模型可能从绝对坐标中获益。相对距离告诉我们两个 token 隔多远，却不直接告诉模型它们离开头有多远。

有些结构还同时关心方向。$n-m$ 与 $m-n$ 的符号不同，但在具体实现和注意力分布中，前后关系怎样被使用，需要结合因果约束和训练任务理解。仅仅看到“相对位置”四个字，并不能推出所有方向、边界和长距离问题都已经解决。

更实际的问题是：模型需要知道相隔多远、谁在前谁在后、是否属于同一段，还是距离序列起点有多远？这些问题对应不同的位置信息需求。

## 从公式到现象，中间隔着训练

RoPE 的推导证明点积可以包含相对位置，但它不会自动告诉我们训练后的模型一定按照人类直觉使用距离。

训练后的注意力头可能关注局部，也可能跨越很远；某些头可能主要使用内容，位置影响较弱；另一些头则可能高度依赖位置。只有在分析权重、注意力分布和具体任务行为后，才能知道这些结构怎样被利用。

所以，我会把论文推导和模型行为分开记录：公式说明“能够怎样表达”，实验说明“在这个设置下实际学到了什么”。把两者混在一起，就容易从数学可能性跳到过度结论。

## 读位置编码论文时的一张检查清单

以后遇到新的位置方法，我会先问下面几个问题：

1. 位置加在输入、注意力分数，还是 Query 和 Key 的变换上？
2. 它主要提供绝对坐标、相对距离，还是两者兼有？
3. 新位置能否由函数生成，还是依赖固定表长？
4. 训练长度与评估长度是否一致？
5. 解码缓存中怎样记录当前位置？
6. 性能提升是否可能来自参数量、训练数据或其他结构变化？

这张清单能把注意力从“又一个新名词”拉回到真正的设计问题。只要信息入口、相对关系、长度范围和推理状态都回答清楚，新方法通常就不再难以理解。

## 把位置编码看成一种接口设计

回顾这些方法，我会把它们理解成模型内部的一种接口：位置信息以什么形式提供，后续模块就按照什么方式读取。

正弦编码把坐标写进输入通道，后续层需要从混合特征里学习读取；相对偏置把距离写进注意力分数，接口更直接；RoPE 则通过旋转约定，让 Query 和 Key 在特定坐标系中完成比较。

接口越明确，某些关系就越容易表达，但也会带来更多约定。使用 RoPE 的代码必须遵守相同的配对、频率和位置缓存规则，就像调用一个函数必须遵守参数约定一样。

这也解释了为什么单纯替换几行公式并不足以完成迁移。模型权重、训练状态和推理代码都可能已经围绕旧接口形成依赖。

把位置编码看作接口之后，我比较新方法时会少关注“公式是否更复杂”，多关注它是否让任务真正需要的关系更容易被读取。这种视角也适用于其他模型模块：好的结构往往不是信息最多，而是信息出现在最合适的位置。

## 我目前形成的理解

如果只保留一条学习路径，我会按下面的顺序复习：

先承认裸自注意力看不到原始词序；再理解正弦编码如何用多频波形提供坐标；接着把注意力问题写成 Query 与 Key 的相对关系；最后推导旋转矩阵为什么能在点积中留下 $n-m$。

这样走下来，RoPE 就不再是突然出现的技巧，而是对前面问题的一种自然回答。

对我而言，最大的收获不是记住几个公式，而是学会追问：**信息究竟在计算的哪一步进入模型？** 一旦把这个问题看清楚，位置编码就不再是一个孤立的模块，而是注意力结构设计中很关键的一部分。
