## 一、Positon Encoding是什么？

![截屏2026-11-04 20.56.48]({{ '/assets/images/posts/transformer-sin-cos-mw24fri4-914846.png' | relative_url }})
<p class="figure-caption">图1:Transformer架构图</p>

回看这张架构图，我们可以发现，在下方不起眼的角落，每一个词嵌入（Embedding）在输入进注意力层（Attention）之前都和一个叫Position Encoding的做了“+”处理。那么你一定会好奇，这个PE（Posinton Encoding）到底是什么？以及为什么要“加”它？

简单来说，位置编码（Positional Encoding，简称 PE）就是一种专门用来标记 Token 在序列中“先后顺序”的向量。

举个直观的例子。假设我们有一个句子“你好世界”，把每个字当成一个 Token，从前往后依次给它们编个号：

- “你” = 0
- “好” = 1
- “世” = 2
- “界” = 3

在概念上，这几个数字就代表了它们各自的绝对位置。但在真实的 Transformer 架构中，PE 不能只是一个简单的数字（比如 [0] 或 [3]），而必须是一个高维向量（其维度需要和词本身的语义向量完全一致，比如 512 维），这样才能直接和词向量相加。

既然我们知道了 PE 在概念上就是给每个词标上“座位号”，那我们不禁要问：为什么非得大费周章地给词向量加上这层位置信息？如果去掉它，Transformer 会怎么样？

## 二、Transformer其实是个盲人？

既然位置编码是给词标记“座位号”，那我们不妨做个脑力实验：如果不加位置编码，直接把句子塞进 Transformer 会发生什么？

答案可能会让你大吃一惊：在 Transformer 眼里，“鹈鹕骑自行车”和“自行车骑鹈鹕”，这两句话是完全相同的。

为什么会这样？这就不得不说到 Transformer 的核心引擎——自注意力机制（Self-Attention） 的天生缺陷。

### 1、Self-Attention 的“置换不变性”

我们回想一下 Self-Attention 是怎么工作的。当模型计算某个词和其他词的关系时，本质上是在做向量的点积（Dot Product）：

$$
\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V
$$

仔细看这个过程：计算 Queries（$Q$）和 Keys（$K$）的点积时，模型只关心词与词之间的**语义相似度**（例如“鹈鹕”和“骑”有多匹配）。但是，点积运算有一个致命的特性：它完全不关心词的位置和顺序。无论“鹈鹕”是在句头还是句尾，只要它的词向量没变，它和“骑”算出来的注意力得分就完全一模一样。在数学上，这被称为**置换不变性（Permutation Invariance）**。

### 2、无序的“词袋模型”

如果用一个形象的比喻：传统的 RNN 像是一个人在排队听演讲，一个词接着一个词按顺序进入脑袋，天然就带有时间的先后顺序；而 Self-Attention 就像是把所有的词一股脑扔进了一个大布袋里，然后同时去抓取它们之间的关系。

在这个“布袋”里：

- 它知道这句话里有“鹈鹕”、“骑”、“自行车”。
- 但它完全看不见谁排在第一、谁排在第二。

如果不人工干预，Transformer 就只是一个极其强大的“词袋模型（Bag-of-Words）”。这种设计理念，虽然让它天然拥有比RNN更强的并行计算能力，但对语言中最基础的“语序”却毫无感知——它天生就是一个无法感知空间顺序的“盲人”。

### 3、机器学习不会emo

我们知道，人类是有感情的，且语序，这个最基础的语言概念，往往包含着人类最难以描述的情感概念。

最简单的例子：“你喜欢她”就代表“她喜欢你”吗？

在自注意力机制（Self-Attention）的逻辑里，这个回答是：“是的，完全没有区别。”

我想很多人都会希望是这个答案吧。

但是机器学习不会 emo，人类会。

在人类的语义空间里，颠倒了语序，往往就颠倒了一整个世界——**那是“暗恋”与“相爱”的距离，也是“得到”与“失去”的遗憾。**

可是在未经过位置修饰的 Self-Attention 眼里，无论词语的顺序如何颠倒，“你”还是那个“你”，“她”也还是那个“她”。它只顾着计算两个词向量在几何空间里的距离与匹配度，却完全听不懂语序背后那沉甸甸的情绪。

如果程序无法感知时间的先后、词语的前后，它就永远无法真正理解人类的语言。

——为了不让大模型继续当这个毫无情商的“盲人”，工程师们必须想办法，把“顺序”这个概念塞进它的脑海里。

## 三、如何设计 PE：一场“试错之旅”

既然大模型是个急需“座位号”的盲人，那我们作为架构师，该怎么把位置信息塞进向量里呢？

你可能会觉得：“这还不简单？给每个词编个号不就得了！”

但正如所有优秀的工程设计一样，最直观的想法往往死得最惨。

### 1、直接标号：绝对位置的数值灾难

最容易想到的直觉是什么？直接给每个词编个绝对的位置序号。

怎么做：第一个词位置是 $1$，第二个是 $2$，第三个是 $3$……直接把这个数字加到词向量上去。

这么做很直观也很容易实现，但是会让模型遇到两个灾难性的问题：

1、**数值爆炸**：在深度学习里，词本身的语义向量（Embedding）就像是一堆温和的小数（数值通常在 $-1$ 到 $1$ 之间跳动）。如果句子很长，到了第 10000 个词，位置编码直接变成了 10000。当一个原本带着细腻语义的小数，被硬生生加上了一个 10000：

$$
\text{最终向量} = \text{语义小数} + 10000 \approx 10000
$$

这就像你在图书馆里正戴着耳机听着轻柔的钢琴曲（词义向量），突然旁边有人开着一台巨型低音炮贴脸狂轰滥炸（位置向量10000）。

在这绝对震撼的音量面前，原本美妙的钢琴曲瞬间被震得粉碎，什么音符都听不见了。对神经网络来说，此时此刻它的“耳朵”里全是被位置数字撑满的轰鸣声，词本身的语义细节就这样被无情地压倒和淹没了。

2、**泛化性为零**：如果在训练时模型见过的最长句子是 512 个词，那它在测试时遇到第 513 个词就会彻底懵圈——因为这个绝对数值它在训练时根本没见过。

综上所述，暴力的直接标号虽然最符合人类直觉、能轻而易举地标明绝对位置，但数值爆炸意味着它在工程可行性上几乎为零。

### 2、简单的归一化：相对位置的感知失效

既然我们之前提到语义向量的数值是很温和的，大多在-1到1之间，那我们把PE的数值也压缩到这个范围不就好了吗？

怎么做？

我们设句子总长度为 $L$，第 $i$ 个词的位置设计成 $i / L$，这样就能让所有位置都被死死锁在 $[0, 1]$ 区间里。

表面上看，这个设计把所有句子的位置都规范到了 $[0, 1]$ 之间，完美解决了数值爆炸的问题。但它带来了一个毁灭性的副作用——“相邻”这个概念彻底失效了。我们可以做个极端对比：

- 在一个只有 5 个词的短句里（$L=5$），相邻两个词之间的距离是：

$$
\Delta = \frac{2}{5} - \frac{1}{5} = 0.2
$$

- 在一个长达 1000 个词的长文本里（$L=1000$），相邻两个词之间的距离变成了：

$$
\Delta = \frac{2}{1000} - \frac{1}{1000} = 0.001
$$

这意味着，在模型的眼里，“相邻”这个概念失去了统一标准——短句里的 0.2 和长句里的 0.2 完全是两个概念。模型根本没法学习到一个普适的相对距离。

这就会带来两个很严重的后果：

- **语义尺度的彻底错乱**：在神经网络的世界里，模型需要学习诸如“距离相近的词通常有强关联（比如主谓宾相邻）”这样的通用规律。如果用归一化方案，模型会彻底迷失：在短句里，代表“紧密相邻”的数字是 0.2；而在长文里，数字 0.2 意味着它们中间隔了足足 200 个词！ 同一个数字 0.2，在不同的场景下代表的物理意义完全相反。

- **长度泛化能力的死亡**：当模型在短句里学会了“距离为 0.001 的两个词毫无关系”时，一旦遇到长文，它会把原本紧密相邻的词（距离也是 0.001）误判为毫无关联。这把“软尺”随着句子的长短不停伸缩，导致模型根本无法建立一个稳定、普适的相对距离感知。

所以说，简单的归一化处理虽然能解决数值不稳定的问题，但对于相对位置感知却彻底失效。

### 3、编码设计：相对位置 or 绝对位置

回过头来看刚才这两次惨败的尝试，可以意识到，我们被卡在了一个两难的死胡同里：

- 第一步的“直接标号”，死磕的是绝对位置（我是第 5 个词），结果因为数值无限膨胀，被“巨型低音炮”般的绝对大小彻底淹没了细腻的词义。

- 第二步的“归一化”，试图通过比例折算来解决范围问题，结果却弄砸了相对距离——这种受制于文本总长度的动态压缩，让模型再也无法在不同长度的句子中建立统一的“相邻”标准。

这其实揭示了位置编码设计中的一个问题：在语言的世界里，我们究竟该追寻什么？

要回答这个问题，我们首先要搞懂两个概念：**绝对位置**和**相对位置**。

- 绝对位置（Absolute Position）：指的是一个词在整条序列里的绝对坐标（比如“我是第 5 个词”）。它决定了文本的宏观结构——比如文章的开头通常是引言，结尾通常是总结。

- 相对位置（Relative Position）：指的是两个词之间的相对距离（比如“词 A 和词 B 之间隔了 3 个词”）。它决定了语法的微观化学反应——无论一句话出现在文章开头还是结尾，“不”和“好”紧紧贴在一起就是否定，隔了五十个字就毫无干系（平移不变性）。

如果只给相对位置，模型就会失去对上下文全局边界的感知；而如果只有粗暴的绝对位置，模型又无法在不同长度的文本中泛化通用的语法规律。

所以小孩子才做选择，我们全都要。

### 4、戴着镣铐跳舞：被约束倒逼出的解法

摆在我们面前的，是一场看似不可能完成的“既要又要”：

- 想要绝对坐标，就容易数值爆炸；
- 想要归一化控制数值，又会把相对距离挤压变形；
- 想要模型能理解相对距离，又不能设计得过于笨重以至于无法并行。

工程的严苛与数学的冷酷，就像一道道沉重的锁链，死死扣住了架构师的手脚。

然而，真正顶级的工程艺术，往往就是戴着镣铐跳舞。如果我们将所有现实痛点拆解开来，会发现一个天才的 Transformer 位置编码系统，被强制套上了四大绝不能打破的约束：

- **约束一：独特的绝对坐标**：每一个位置 $pos$ 必须拥有独一无二的编码，模型能够明确区分“第 1 个词”和“第 100 个词”。

- **约束二：稳定的数值边界**：无论句子有多长（哪怕到了第 10,000 个词），编码的数值范围必须死死控制在一个温和的区间内（比如 $[-1, 1]$），绝不能发生数值爆炸去压倒语义向量。

- **约束三：平滑的长度泛化**：编码必须具有连续性和平滑性，测试时遇到训练时没见过的更长句子，模型也能平滑外推，而不是直接懵圈。

- **约束四：隐式的相对距离表达**：绝对位置编码 $PE_{pos}$ 与 $PE_{pos+k}$ 之间，必须存在某种明确的数学关系，使得模型在计算注意力（Attention 内积）时，能够直接、无损地推导出它们的相对距离 $k$。

### 5、数学倒逼：什么函数能同时满足这四大条件？

把这四个约束摆在桌上，数学的奇迹就开始发生了。

- 想要“数值有界”，同时又要“无限延伸且平滑”？你脑海里出现的第一个数学工具一定是：周期性函数（Periodic Functions）。
- 在所有周期函数里，谁最平滑、最连续、且值域永远被死死锁定在 $[-1, 1]$ 之间？答案呼之欲出——正弦（$\sin$）与余弦（$\cos$）函数。

- 更有意思的是约束四（相对距离）：在三角函数里，有一个全人类高中都学过的神仙定理——和差化积 / 三角加法公式：$\sin(\alpha + \beta) = \sin\alpha\cos\beta + \cos\alpha\sin\beta$，这意味着，只要给每一个维度配一对不同频率的 $\sin$ 和 $\cos$，位置 $pos+k$ 的编码就可以表示为位置 $pos$ 的编码经过一个只与相对偏移量 $k$ 相关的线性变换。

原论文里是这么写的：

> “We chose the sinusoidal version because it would allow the model to attend by relative positions, since for any fixed offset $k$, $PE_{pos+k}$ can be represented as a linear function of $PE_{pos}$.”

翻译一下就是：“我们选择正弦/余弦版本，是因为它能让模型学会根据相对位置来进行注意力计算，因为对于任何固定的偏移量 $k$，$PE_{pos+k}$ 都可以表示为 $PE_{pos}$ 的线性函数。”

### 6、天才般的PE设计

至此，我们以数学的视角，从约束条件反向推出需要什么样的函数后，再回过头来看当年“谷歌八子”的设计就不会那么意外了。

对于位置 $pos$ 和向量的第 $i$ 个维度，编码公式为：

$$
PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{\frac{2i}{d_{\text{model}}}}}\right)
$$

$$
PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{\frac{2i}{d_{\text{model}}}}}\right)
$$

初看这个公式，分母上的 $10000$ 和指数幂可能会让人觉得有点眼花缭乱。但如果我们换个物理视角去审视它，就会发现这其实是一场精心编排的“高低频交响乐”：

- **微观的高频维度（$i$ 较小）**：分母很小，意味着波长极短。随着位置 $pos$ 稍微增加一点（比如从词 1 到词 2），正弦波的值就会剧烈翻转。它就像时钟里的“秒针”，极其敏感地捕捉着局部的、相邻词之间的微观语法关系（如主谓紧贴）。

- **宏观的低频维度（$i$ 较大）**：分母极大（最大可达 $10000$），意味着波长极长。词语每走几步，它的值几乎没什么变化，需要跨越成百上千个词，波形才缓慢起伏一次。它就像时钟里的“时针”甚至“日历”，死死锚定着全局的长文本宏观位置。

通过将不同波长的 $\sin$ 和 $\cos$ 在不同的维度上进行拼接（也就是将 $d_{\text{model}}$ 个维度的波形叠加），每一个位置 $pos$ 都获得了一个独一无二、高低频交织的高维指纹。

## 四、从公式到实现：每个token的PE到底怎么算出来的？

在上一节中，我们从纯粹的数学约束出发，倒逼出了正弦余弦编码的物理形态。但对于工程师来说，“看懂公式”和“真正理解它怎么落到内存里”之间，还隔着一道代码的鸿沟。

下面我们就剥离所有抽象的符号，拿一个真实的 Token 走一遍计算全流程，看看它究竟是怎么从一个标量索引，变成一个充满高低频信息的高维向量的。

### 1、维度切分与频率底座：分母里的 $10000$ 究竟是怎么来的？

首先回顾一下公式的核心分母：

$$
\text{freq}_i = \frac{1}{10000^{\frac{2i}{d_{\text{model}}}}}
$$

很多初学者会被 $10000$ 这个数字吓住。其实它的几何意义极其直观：它定义了波长（或周期）从最小到最大的变化范围。

- 当维度索引 $i=0$ 时，分母为 $10000^0 = 1$，此时角频率最高，波长最短；

- 当维度索引 $i \to \frac{d_{\text{model}}}{2}$ 时，分母趋近于 $10000^1 = 10000$，此时角频率最低，波长漫长。

在这两个端点之间，分母按照等比数列（指数级）平滑延伸。这种按对数均匀分布的波长序列，保证了不同维度能够以非常合理的步长去分工覆盖“从近到远”的物理空间。

### 2、偶偶奇奇：$\sin$ 和 $\cos$ 的维度分工

为什么编码向量里既要有 $\sin$ 又要有 $\cos$？

- 组成正交对：在同一种频率下，$\sin(\theta)$ 与 $\cos(\theta)$ 相相位差了 $90^\circ$（即 $\frac{\pi}{2}$）。它们共同构成了一个二维平面上的坐标系，避免了单一正弦波在零点附近导数与采样值信息的缺失。

- 偶数维与奇数维交错：**偶数维度（$2i$）**：填充 $\sin$ 值；**奇数维度（$2i+1$）**：填充 $\cos$ 值。

从具体操作来说，假设我们有n个token组成的序列，模型隐藏层维度d=512，现在我们要来算每个token的位置编码。

首先，我们观察上面两个函数图像，可以看到每张图里我们画了5条曲线，分别是i = 0，64，128，192，255。

如果我们把从 i =0到 i = 255中间的每曲线都画出来，那么上面的两张图片里，每张图片的曲线数量都会从5条变成256条，加起来一共是512条。

下面我们固定pos为1，对于上面两张函数图（各有256条曲线），我们按照x = 1这条竖线，竖着切下来，会发现256条曲线和这条x=1的竖线都有一个交点;

在$PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{\frac{2i}{d_{\text{model}}}}}\right)$里：它们的坐标是（1，y_0),(1,y_2),...,(1,y_510);

在$PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{\frac{2i}{d_{\text{model}}}}}\right)$里：它们的坐标是（1，y_1),(1,y_3),...,(1,y_511);

这里的y分别就是位置1这个token在各个奇数维和各个偶数维下的编码向量的数值，我们把它们拼在一起就得到了pos = 1时的PE：[y_0,y_1,...,y_510,y_511]。一个维度为512的向量。

接下来，对每个位置做同样的操作，从pos = 1到pos = n重复做n次，就能得到大小为（n，512）的矩阵，利于批处理。

### 3、 动手实算：假设 $pos=1, d_{\text{model}}=4$

我们来做一次“手动 CPU 计算”。假设词嵌入维度 $d_{\text{model}} = 4$，当前 Token 处于句子的第 1 个位置（$pos=1$）。

Step 1: 计算频率（维度配对 $i \in \{0, 1\}$）

- 对于第一组维度（$i=0$）：$\text{freq}_0 = \frac{1}{10000^{0/4}} = 1.0$

- 对于第二组维度（$i=1$）：$\text{freq}_1 = \frac{1}{10000^{2/4}} = \frac{1}{\sqrt{10000}} = 0.01$

Step 2: 计算旋转角度 $\theta = pos \times \text{freq}$

- $\theta_0 = 1 \times 1.0 = 1.0 \text{ rad}$

- $\theta_1 = 1 \times 0.01 = 0.01 \text{ rad}$

Step 3: 交替填充 $\sin$ 与 $\cos$ 到向量中

- 维度 0（偶数维 $2\times 0$）：$\sin(\theta_0) = \sin(1.0) \approx \mathbf{0.8415}$

- 维度 1（奇数维 $2\times 0 + 1$）：$\cos(\theta_0) = \cos(1.0) \approx \mathbf{0.5403}$

- 维度 2（偶数维 $2\times 1$）：$\sin(\theta_1) = \sin(0.01) \approx \mathbf{0.0100}$

- 维度 3（奇数维 $2\times 1 + 1$）：$\cos(\theta_1) = \cos(0.01) \approx \mathbf{0.99995}$

最终，位置 $pos=1$ 的 4 维位置编码向量就被精准地算出来了：$$PE_{1} = [0.8415,\ 0.5403,\ 0.0100,\ 0.99995]$$

你可以清晰地看到：前两个维度（高频）发生了剧烈的数值跳变，后两个维度（低频）则几乎死死保持在接近 1 的平缓状态。

### 4 、代码高效实现：PyTorch 向量化矩阵拼接

在实际开发中，我们绝不可能用 for 循环一个词一个词去算，而是利用广播机制（Broadcasting）和外积运算，一行代码直接生成一张大表（Position Embedding Table）。

下面是经典且优雅的 PyTorch 向量化实现：

```python
import torch
import torch.nn as nn

class SinusoidalPositionalEncoding(nn.Module):
    def __init__(self, d_model: int, max_len: int = 5000):
        super().__init__()
        
        # 1. 初始化全 0 的位置编码矩阵 (max_len, d_model)
        pe = torch.zeros(max_len, d_model)
        
        # 2. 生成绝对位置索引列向量 pos: shape (max_len, 1)
        position = torch.arange(0, max_len, dtype=torch.float).unsqueeze(1)
        
        # 3. 计算衰减频率项 (利用 exp 和 log 避免大数幂运算的浮点误差)
        # 2i/d_model 的递进步长为 2
        div_term = torch.exp(
            torch.arange(0, d_model, 2).float() * (-torch.log(torch.tensor(10000.0)) / d_model)
        )
        
        # 4. 向量化矩阵外积计算：(max_len, 1) * (d_model/2,) -> (max_len, d_model/2)
        # 偶数维填 sin，奇数维填 cos
        pe[:, 0::2] = torch.sin(position * div_term)
        pe[:, 1::2] = torch.cos(position * div_term)
        
        # 5. 增加 Batch 维度并注册为 buffer（不参与梯度更新，但随模型保存）
        pe = pe.unsqueeze(0)  # shape: (1, max_len, d_model)
        self.register_buffer('pe', pe)

    def forward(self, x: torch.Tensor) -> torch.Tensor:
        """
        x: [batch_size, seq_len, d_model]
        直接将位置编码加到输入向量上（Add 操作）
        """
        seq_len = x.size(1)
        return x + self.pe[:, :seq_len, :]
```

这样我们就把公式推导、几何直觉、单点手算到 PyTorch 向量化代码彻底打通了！

## 五、结语：天才般的权衡，与通往未来的旋转之门

回望 2017 年那篇改变了整个 AI 时代的论文 《Attention Is All You Need》，“谷歌八子”提出的正弦余弦位置编码（Sinusoidal PE），堪称深度学习历史上的一次工程学与数学交织的“神来之笔”。

### 1. 天才般的设计：它赢在哪里？

- 不花一分钱的泛化（无参数）：它不需要像词嵌入那样靠海量数据去反向传播“训练”位置权重，而是一套纯粹由数学公式决定的硬编码。这意味着，哪怕测试集出现了训练时从未见过的超长文本，它也能凭借三角函数的周期性自然外推。
- 巧妙的“既要又要”：通过一套极其克制的公式，它完美兼顾了绝对坐标的唯一性、数值的有界稳定、以及通过三角恒等式隐式表达相对距离的能力。

### 2. 无法回避的局限：原版 PE 的遗憾

然而，随着大模型迈入数万甚至数百万上下文的“长文本时代”，初代正弦余弦编码的缺陷也逐渐暴露了出来：

- 加法残差的干扰：它是直接将位置编码“加（Add）”到词向量里的。随着网络层数越来越深、维度越来越大，这种暴力叠加可能会在一定程度上模糊或冲淡原本纯粹的语义向量。
- 隐式相对距离的精度损耗：虽然数学上它支持通过线性函数推导相对距离，但这种“隐式”表达对模型的要求太高。在超长距离的注意力计算中，模型往往很难完美利用好这种复杂的三角交叉项。

### 3. 终极破局：通往 RoPE 的时空之门

正因如此，现代大语言模型（如 LLaMA、Qwen、Mistral 等）在架构演进时，毫不犹豫地抛弃了原版正弦余弦的“加法残差”路线，转向了一种更优雅、更彻底的几何方案——**把位置直接作用在 Query 和 Key 的向量空间里，用纯粹的正交旋转矩阵来实现相对位置的精确控制**。

这，**就是统治了当今开源大模型江山的 RoPE（Rotary Position Embedding，旋转位置编码）。**
