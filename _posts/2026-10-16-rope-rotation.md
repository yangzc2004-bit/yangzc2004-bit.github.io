RoPE 的公式看起来比正弦位置编码更复杂，但它的几何直觉非常直接：**位置每向前走一步，向量就转过相应的角度。**

位置不再是贴在词向量外面的一张标签，而是变成 Query 和 Key 的方向变化。

这篇文章会把 RoPE 拆成四层：二维几何、复数形式、注意力点积和工程实现。最后还会讨论长度外推，因为“能计算新位置”和“能理解新长度”经常被混为一谈。

## 先看二维：旋转改变方向，不改变长度

二维旋转矩阵写作：

$$R(\theta)=
\begin{pmatrix}
\cos\theta & -\sin\theta\\
\sin\theta & \cos\theta
\end{pmatrix}$$

作用在向量 $v=(x,y)^T$ 上：

$$R(\theta)v=
\begin{pmatrix}
x\cos\theta-y\sin\theta\\
x\sin\theta+y\cos\theta
\end{pmatrix}$$

如果把向量看成从原点出发的箭头，旋转只会改变它指向哪里，不会改变它有多长。因此：

$$\|R(\theta)v\|=\|v\|$$

这个性质很重要。位置变大时，RoPE 不会因为旋转角变大就机械地放大或缩小 Query、Key 的范数。位置改变的是方向。

## 旋转矩阵的两条关键性质

第一条是连续旋转可以相加：

$$R(a)R(b)=R(a+b)$$

第二条是转置等于反向旋转：

$$R(a)^T=R(-a)$$

也可以用 $R(a)^{-1}=R(-a)$ 理解，因为旋转矩阵是正交矩阵，转置就是逆。

RoPE 的相对位置能力，几乎就从这两条性质里长出来。只要位置被写成角度 $m\theta$，那么两个位置之间的关系就可以转化为角度差。

这与使用一张位置嵌入表很不一样。位置表首先提供的是每个位置的一组特征，而旋转提供的是一种具有代数规律的变换。

## 用复数可以写得更短

如果把二维向量 $v=(x,y)$ 看成复数 $z=x+iy$，乘以 $e^{i\theta}$ 就是旋转：

$$e^{i\theta}z=(\cos\theta+i\sin\theta)(x+iy)$$

展开实部和虚部，正好对应旋转矩阵的两行。

复数形式下，位置 $m$ 的旋转是：

$$z_m=e^{im\theta}z$$

共轭对应反向旋转，因此两个复数做内积时，也会出现 $e^{i(n-m)\theta}$。

矩阵和复数不是两种不同方法，而是同一直觉的两种语言。矩阵更方便与深度学习代码连接，复数更方便看清“位置变成相位”的含义。

## 把位置放进 Query 和 Key

设位置 $m$ 上的原始 Query 为 $q$，位置 $n$ 上的原始 Key 为 $k$。RoPE 分别施加与位置有关的旋转：

$$q_m=R(m\theta)q,\qquad k_n=R(n\theta)k$$

这里最好先区分两组符号：$q$、$k$ 是内容投影得到的向量，$q_m$、$k_n$ 是加入位置后的向量。RoPE 并没有替代 $W_Q$ 和 $W_K$，而是在它们之后继续施加位置变换。

于是典型流程是：

$$q=x_mW_Q,\qquad k=x_nW_K$$

$$q_m=R_m q,\qquad k_n=R_n k$$

其中 $R_m$ 表示由位置 $m$ 和多频参数共同决定的块对角旋转矩阵。

## 核心推导：点积只留下相对位置

计算注意力匹配时：

$$
\begin{aligned}
q_m^Tk_n
&=q^TR(m\theta)^TR(n\theta)k\\
&=q^TR(-m\theta)R(n\theta)k\\
&=q^TR((n-m)\theta)k
\end{aligned}
$$

绝对位置 $m$ 和 $n$ 不再分别留在结果里，剩下的只有相对距离 $n-m$。

这就是为什么 RoPE 能同时做到两件事：施加旋转时使用绝对位置，进入注意力点积后却得到显式的相对位置关系。

如果整段序列向后平移 $c$ 个位置，位置变成 $m+c$ 和 $n+c$，点积仍然是：

$$q^TR((n+c-m-c)\theta)k=q^TR((n-m)\theta)k$$

这就是整体平移不改变相对位置关系。

## 这不意味着注意力只看距离

看到 $n-m$ 后，很容易把 RoPE 误解成一种纯粹的相对距离评分。实际上，点积里还保留着 $q$ 和 $k$：

$$q^TR((n-m)\theta)k$$

内容仍然决定向量的方向与长度，位置只是改变它们之间的相对方向。

因此，最终注意力分数是内容与位置共同作用的结果。相同距离的两个 token 不会因为距离相同就得到相同分数；不同内容会产生不同的 $q$ 和 $k$。

更准确的说法是：RoPE 让相对位置成为点积的一个结构化因素，而不是让距离取代内容。

## 高维怎么办：分组旋转

实际模型的向量远不只二维。RoPE 把维度两两分组，第 $i$ 组使用频率：

$$\theta_i=10000^{-2i/d}$$

于是每一组都可以看成一个转速不同的二维平面。

假设一个八维向量，可以分成四组：

$$(q_0,q_1),\quad(q_2,q_3),\quad(q_4,q_5),\quad(q_6,q_7)$$

每组都根据同一个位置 $m$ 旋转，但角速度分别是 $\theta_0,\theta_1,\theta_2,\theta_3$。最终变换矩阵是由许多二维旋转块组成的块对角矩阵：

$$R_m=\operatorname{diag}\left(R(m\theta_0),R(m\theta_1),\ldots\right)$$

因为不同块之间不会相互混合，二维推导可以逐组应用，最后再合起来。

## 多频设计在表达什么

高频组随位置变化快，适合区分相邻位置；低频组变化慢，提供更长范围的坐标。

这与正弦位置编码使用的多频思想一脉相承，只是这里不再把波形加到输入上，而是直接改变注意力中的向量方向。

可以用时钟来想象：一个指针每步转很多，另一个指针每步只转一点。单独看快指针，可能很快转过一整圈；结合慢指针，就能区分周期之外的位置。

不过，多频并不意味着每个频率都承担固定、清晰的人类语义。它只是提供不同尺度的位置变化，具体怎样被注意力头使用仍由训练决定。

## 一个最小 NumPy 实现

下面的实现采用相邻维度配对：

```python
import numpy as np

def apply_rope(x, positions, base=10000):
    # x: [sequence_length, dimension]
    if x.shape[-1] % 2 != 0:
        raise ValueError("RoPE requires an even dimension")

    d = x.shape[-1]
    inv_freq = base ** (-np.arange(0, d, 2) / d)
    angles = positions[:, None] * inv_freq[None, :]
    cos, sin = np.cos(angles), np.sin(angles)

    even, odd = x[:, 0::2], x[:, 1::2]
    out = np.empty_like(x)
    out[:, 0::2] = even * cos - odd * sin
    out[:, 1::2] = even * sin + odd * cos
    return out
```

这里 `even` 和 `odd` 分别对应每一对维度的 $x$ 和 $y`。两行赋值就是：

$$x'=x\cos\theta-y\sin\theta$$

$$y'=x\sin\theta+y\cos\theta$$

实际实现还需要处理批次、注意力头、缓存和张量布局，但数学操作就是这些正弦、余弦与交叉相乘。

## 另一种常见布局：前后半维配对

上面的代码使用 `(0,1)`、`(2,3)` 这样的相邻配对。有些实现会把向量分成前后两半，让 `(0,d/2)`、`(1,d/2+1)` 配对。

两者不是谁对谁错，而是不同的数据布局。真正危险的是混用：如果权重按照一种布局训练，推理却用另一种布局旋转，即使公式相同，结果也会不一致。

因此，在阅读不同框架的 RoPE 代码时，除了公式，还要检查：

- 哪些维度被配成一对；
- 正弦和余弦如何广播；
- 输出是否保持原来的维度顺序；
- 权重与缓存是否使用同一约定。

很多“公式明明对了，结果却不对”的问题，最后都出在这些细节。

## 训练与解码时的位置有什么不同

训练时通常一次处理整段序列，位置可以直接写成：

```python
positions = np.arange(sequence_length)
```

自回归解码则不同。模型每步只处理一个新 token，同时读取之前的 KV 缓存。如果缓存里已经有 `past_length` 个 token，新 token 的位置应当是 `past_length`，而不是 0。

例如，已经处理到第 127 个 token，新 token 的 Query 就应该按照位置 127 旋转。缓存中的 Key 也必须保留它们各自写入时的位置旋转结果。

如果把新 token 错当成位置 0，Query 与历史 Key 的相对位置就会错误。模型不会一定报错，因为张量形状完全合法，但语义已经悄悄变了。

这也是 RoPE 工程实现中很典型的一类问题：数学公式没有变化，状态管理却决定了公式是否被正确使用。

## 为什么旋转适合与缓存配合

KV 缓存保存的是历史 token 的 Key 和 Value。对于 RoPE，历史 Key 在写入缓存时就已经按各自位置旋转，之后不需要每步重新旋转整个序列。

新 token 到来时，只需要计算当前位置的 Query 和 Key，把新 Key 加入缓存，再让当前 Query 与所有历史 Key 做点积。

绝对位置持续增加，但相对位置性质仍然保留。这样既避免重复计算，也保持位置约定一致。

当然，缓存越长，注意力计算和显存占用仍然会增加。RoPE 解决的是位置表示与缓存配合的问题，不会让长序列的计算成本消失。

## RoPE 与正弦位置编码到底是什么关系

两者都使用不同频率的正弦和余弦，因此看起来很像。但它们进入模型的位置不同。

正弦位置编码把位置向量加到输入词嵌入上：

$$x_{\text{input}}=x_{\text{token}}+PE_{pos}$$

RoPE 则把正弦和余弦组织成 Query、Key 的旋转：

$$q_m=R_m q,\qquad k_n=R_n k$$

前者把位置作为内容特征的一部分，后者把位置作为注意力关系的变换。因此，RoPE 不是简单地把原论文的公式移到另一行，而是改变了位置信息参与计算的方式。

两者共享多频思想，却对应不同的结构设计。

## RoPE 与其他相对位置方法

相对位置信息也可以通过注意力偏置加入。例如，可以在注意力分数上增加与 $n-m$ 有关的项：

$$\operatorname{score}_{mn}=\frac{q_mk_n^T}{\sqrt{d_k}}+b_{n-m}$$

这时，内容点积和位置偏置在形式上分开。RoPE 则把位置融入点积本身。

两者各有直觉：显式偏置更像直接学习“相隔多远应该加多少分”，RoPE 更像让内容向量在位置决定的坐标系中比较方向。

不能仅凭公式判断所有任务上的优劣。参数量、训练稳定性、最大距离、实现效率和模型规模都会影响结果。

## 旋转保留范数，但注意力仍会变化

前面提到 $\|R(\theta)v\|=\|v\|$。这说明旋转本身不改变单个向量的长度。

但 Query 和 Key 的方向发生变化，点积可以改变，注意力权重也会改变。保留范数不等于保留分数。

RoFormer 论文还讨论了随相对距离增加而衰减的依赖特性。这个性质需要结合具体推导理解，不能简单记成“距离越远，分数必然越小”。内容项、正负号和不同频率都会影响最终分数。

因此，不要把 RoPE 想成一个固定的距离惩罚函数。它不是硬性屏蔽远程 token，也不是对所有内容统一衰减。

## RoFormer 和 RoPE 不是同义词

RoPE 是 Rotary Position Embedding，即旋转位置编码。RoFormer 是采用 RoPE 的 Transformer 模型。

类似地区分“注意力机制”和“使用注意力机制的模型”，有助于避免把方法与整体架构混在一起。

当我们说“RoPE 的优点”时，应该聚焦位置表示；当我们说“RoFormer 的实验结果”时，还涉及数据、训练配置和模型其他部分，不能把所有差异都归因于位置编码。

## 三个容易产生的误解

第一，RoPE 不是把位置编码加到词嵌入上。它主要作用于注意力中的 Query 和 Key。

第二，RoPE 不等于无限上下文。函数可以给新位置生成旋转角，但模型能否可靠处理超出训练分布的长度，是另一个问题。

第三，RoPE 不是只根据距离决定注意力。内容和位置共同参与点积，二者不能相互替代。

## 为什么长度外推仍然困难

这里需要区分三个层次：

**表示可计算。** 任意新位置都能计算正弦和余弦，旋转矩阵不会因为位置超出训练长度就失效。

**工程可运行。** 只要缓存和形状允许，模型可以继续处理更长输入。

**学习可泛化。** 模型在训练中学到的注意力模式，是否仍然适合更长距离的关系，需要实验验证。

第三个层次最难。训练时，某些频率可能只在特定位置范围内出现特定模式；推理长度变长后，模型会遇到训练时没有充分学习的相位和依赖组合。

因此，“RoPE 不需要位置表”只解决了表示生成的一部分问题，不会自动保证长上下文能力。

## 怎样验证一个 RoPE 实现

如果自己动手实现，可以写几个不依赖训练的小测试。

**恒等测试。** 位置 0 的旋转角为 0，因此 $R_0q=q$。如果位置 0 都改变向量，说明公式或布局有误。

**范数测试。** 任意位置旋转前后，向量的二范数应在数值误差范围内相同。

**合成测试。** 连续施加位置 $a$ 和位置 $b$ 的旋转，应与位置 $a+b$ 的一次旋转一致。

**相对位置测试。** 对同一组 $q$、$k$，比较位置 $(m,n)$ 与 $(m+c,n+c)$ 的点积，两者应相同。

**配对测试。** 手工计算一对二维维度的结果，与向量化实现逐项比较。

**缓存测试。** 整段一次性计算与逐 token 解码，在相同位置和相同输入下应得到一致结果。

这些测试不能证明模型训练效果，却能证明代码确实实现了预期的数学结构。

## 从矩阵到代码的一次逐项对照

为了避免“公式看懂了，代码却只是照着抄”，可以把一对维度完整对应起来。

设某一对输入是 $x$ 和 $y$，位置为 $m$，当前频率为 $\theta_i$。先计算角度：

$$a=m\theta_i$$

再计算两个三角函数值 $\cos a$ 和 $\sin a$，最后写：

$$x'=x\cos a-y\sin a$$

$$y'=x\sin a+y\cos a$$

代码中的 `out[:, 0::2]` 对应所有 $x'$，`out[:, 1::2]` 对应所有 $y'$。`angles[:, i]` 则把不同位置和不同频率组合起来。

这一步看似简单，却特别适合检查理解。如果能不看公式，独立说明 `even * sin + odd * cos` 为什么对应 $y'$，就说明已经从“会调用函数”走到了“理解旋转方向”。

如果再把 positions 全部设为 0，输出应该与输入相同；如果把某个位置的角度设为 $\pi/2$，二维结果应该变成 $(-y,x)$。这些具体例子比只比较最终张量形状更能发现错误。

## 频率、精度和计算开销

RoPE 需要正弦、余弦和逐对乘法，因此并非完全没有计算成本。只是相对于大型矩阵乘法，这部分通常不是最主要的开销，而且三角函数可以预先计算并缓存。

缓存时需要考虑序列最大位置、维度、设备和数据类型。低精度推理中，角度计算和缓存转换的方式可能影响数值表现。把高精度计算结果直接存入低精度缓存，与全程使用低精度计算，不一定得到完全相同的误差分布。

频率底数也不只是一个可以随手替换的数字。它决定不同维度随位置变化的角速度范围，与训练长度和模型已经学到的位置模式有关。改变底数可能改变长上下文表现，但不能脱离训练与评估单独判断。

因此，工程调优时应该记录完整设置，而不是只写“使用了 RoPE”。配对方式、频率、缓存位置和精度，都是复现结果所需的信息。

## RoPE 不会改变注意力的全部难点

位置问题解决后，长序列仍然面临计算和显存成本。标准注意力的 token 两两关系不会因为旋转就减少，KV 缓存也仍然随长度增长。

同时，相对位置可表达不等于模型能自动发现所有长距离依赖。训练数据是否提供足够例子、优化是否稳定、上下文是否包含干扰信息，都会影响实际表现。

把这些问题分开，能避免把长上下文研究简化成位置编码竞赛。位置表示是重要组成部分，但还需要注意力计算、缓存管理、训练策略和数据共同配合。

## 继续阅读时可以追问的问题

如果之后阅读 RoPE 的变体或长上下文改进，我会保留下面几个问题：

1. 改动的是频率、旋转角、注意力公式，还是训练过程？
2. 改动是否保持了相对位置性质？
3. 它与已有 KV 缓存和维度布局是否兼容？
4. 长上下文收益来自结构本身，还是额外训练？
5. 在不同任务和不同长度上，结果是否一致？

这些问题能把新方法与核心 RoPE 联系起来。无论名称怎样变化，最终都要回到角度、点积、相对位置和实际推理行为。

## 从 RoPE 看归纳偏置

RoPE 最值得学习的地方，不只是相对位置公式，而是它把一种任务直觉转化成了模型结构。

我们直觉上认为，序列整体平移后，同一对 token 的关系不应该改变。RoPE 用旋转矩阵的合成性质，把这种直觉变成点积中的数学恒等式。它没有强迫注意力只看相对距离，却让这种关系天然可用。

这就是归纳偏置的一种具体形式：不直接规定答案，而是让模型更容易学习某类关系。

理解这一点后，就可以用同样思路分析其他结构。卷积把局部性和平移共享写进计算，注意力把内容相关的信息交互写进计算，RoPE 则把位置平移下的相对关系写进点积。

它们都在回答“哪些规律值得被预先放进结构”。结构并不替代数据，而是改变数据需要证明什么、模型需要从头学习什么。

当之后看到一种新的位置方法时，我也会先寻找它对应的任务直觉，再看公式如何实现。这样比从公式第一行开始硬背，更容易理解方法为什么被设计成这样。

## 我会怎样记住它

如果只保留一条主线，我会记住：

> 位置决定旋转角，旋转角决定点积中的相对关系。

矩阵公式是在严格表达这件事，复数形式是在简化表达这件事，多频分组是在把这件事扩展到高维，缓存实现则是在让这件事适用于逐 token 推理。

至于代码，只是让每一对维度完成一次正确方向、正确位置、正确布局的旋转。

真正理解 RoPE 后，最值得带走的不是某个固定底数，而是一种设计思路：**如果希望模型学习关系，可以尝试把信息直接写进关系计算，而不只是附加在输入上。**
