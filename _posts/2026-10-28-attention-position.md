第一次看到自注意力时，很容易把它理解成“让句子里的词互相交流”。这个直觉没有错，但少了一半：如果只有内容，没有位置，它其实不知道谁在谁前面。

这篇文章不只给出“需要位置编码”的结论，还会从公式、例子和实验三个角度说明：为什么裸自注意力看不到原始词序，以及位置编码究竟改变了什么。

## 一个词序改变语义的例子

“猫追狗”和“狗追猫”使用的 token 完全相同，只是排列不同。对人来说，语序直接决定主语和宾语；对裸自注意力来说，两组输入却只是一组相同的内容特征。

![相同词语以不同顺序排列的示意图]({{ '/assets/images/posts/attention-order.svg' | relative_url }})
<p class="figure-caption">内容相同不代表顺序相同，而顺序往往就是语义。</p>

问题不在于注意力权重不够复杂，而在于公式里根本没有“第几个位置”这一维度。

类似的例子还有很多：

- “甲给乙一本书”和“乙给甲一本书”；
- “先加激活函数，再做归一化”和“先做归一化，再加激活函数”；
- “收入增长，利润下降”和“利润增长，收入下降”。

词序不仅改变句子是否通顺，也会改变事件的方向、步骤的先后和因果的解释。模型如果要把语言当作序列处理，就必须获得这种信息。

## 从公式看排列问题

单头自注意力写成：

$$\operatorname{Attention}(Q,K,V)=\operatorname{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

其中 $Q=XW_Q$、$K=XW_K$、$V=XW_V$。

输入 $X$ 的每一行对应一个 token。假设用置换矩阵 $P$ 打乱输入行，得到 $PX$。由于线性变换逐行进行，新的 Query、Key、Value 也会按同样方式置换：

$$Q_P=PXW_Q=PQ$$

同理，$K_P=PK$，$V_P=PV$。

新的注意力分数矩阵为：

$$Q_PK_P^T=PQ(PK)^T=PQK^TP^T$$

$P$ 在左侧负责置换行，$P^T$ 在右侧负责置换列。softmax 逐行进行，因此：

$$\operatorname{softmax}(PQK^TP^T)=P\operatorname{softmax}(QK^T)P^T$$

再乘上置换后的 $V$：

$$P\operatorname{softmax}(QK^T)P^TPV=P\operatorname{softmax}(QK^T)V$$

最终得到：

$$\operatorname{Attention}(PX)=P\operatorname{Attention}(X)$$

这就是**置换等变**：输入换顺序，输出也按相同方式换顺序，但每个位置内部表示的计算规则没有变化。

## 置换等变和置换不变有什么区别

这两个术语看起来很像，却描述不同的结果。

置换不变是：输入打乱后，输出完全不变。例如，对一个集合求和，无论元素怎样排列，总和都一样。

置换等变是：输入打乱后，输出跟着同样打乱。例如，对序列中的每个元素独立做平方，输出位置会随输入位置一起移动。

裸自注意力属于后者。它并不是把整个序列压成一个完全不受顺序影响的数，而是每个 token 都得到一个输出，只是这个输出所依赖的关系网络不认识原始编号。

对于序列建模，两者都说明模型没有额外获得原始词序。

## 用两个 token 走一遍计算

假设序列只有 $x_1$ 和 $x_2$ 两个 token。注意力第一行关心“第一个位置应该从其他位置拿什么信息”，第二行关心第二个位置。

如果把输入交换为 $x_2$、$x_1$，那么新的第一行就变成了原来的第二行，新的第二行变成原来的第一行。注意力权重只是在行和列上同步交换，没有出现一个额外项告诉模型：“刚才的第一个 token 现在到了第二位。”

因此，模型可以看到 $x_1$ 和 $x_2$ 的内容，却无法仅凭裸公式恢复它们的原始先后。

这也是为什么多头、增加层数或增大维度不能从根本上替代位置信息。它们能让内容计算更复杂，却没有自动增加一个位置坐标。

## 词向量本身不能解决吗

词嵌入可以区分“猫”和“狗”，却不天然知道“猫”出现在第 1 位还是第 99 位。模型在不同位置看到同一个词时，得到的初始向量通常相同。

当然，训练数据中的词向量可能包含某些上下文统计信息，但这与明确的位置表示不是一回事。我们不能指望一个静态的词向量同时承担词义和坐标。

有人会问：不同的 token 在句子里有不同作用，模型能不能从内容猜出位置？它确实可以学到某些统计倾向，例如句首更可能出现某些词，但这只是概率线索，不是稳定坐标。对于相同 token 重复出现、代码重排或更长序列，单靠内容猜测尤其不可靠。

因此，需要给每个位置一种可区分的表示。

## 位置编码提供了什么新变量

加入位置后，输入不再只有 $x_i$，而是同时包含位置 $i$。最简单的写法是：

$$x_{\text{input},i}=x_{\text{token},i}+PE_i$$

此时，同样的 token 放在位置 1 和位置 2，会得到不同的模型输入。

置换输入时，如果 token 与位置编码错误地一起重排，就会变成另一个问题：它可能只是把整段编码后的序列重新排列。真正用于说明位置作用的，是让位置编码仍然绑定当前坐标，而不是让位置标签跟着 token 一起走。

换句话说，位置信息必须表达“现在处于第几个槽位”，而不是“这个 token 原来在第几个位置”的标签游戏。

## 正弦位置编码的直觉

Transformer 原论文使用不同频率的正弦与余弦函数：

$$PE_{(pos,2i)}=\sin\left(\frac{pos}{10000^{2i/d}}\right),\qquad PE_{(pos,2i+1)}=\cos\left(\frac{pos}{10000^{2i/d}}\right)$$

每个维度像一枚速度不同的指针。高维组合起来后，不同位置形成不同的波形“指纹”。

它与词向量相加，而不是替换词向量。这样，内容特征和位置特征被放在同一份输入里。后面的注意力层可以同时利用两者，而不是只处理词义。

如果把位置 $pos$ 看成时间，不同频率就像时钟的不同刻度。快刻度帮助区分相邻位置，慢刻度帮助表达更长跨度。单个正弦值会周期重复，多组频率组合则提供了更丰富的位置结构。

## 为什么可以直接相加

词嵌入和位置嵌入被设计成相同维度，相加不会增加输入宽度，也不会改变后续矩阵计算的接口。

更重要的是，加法保留了两种来源：token 决定“这是什么”，position 决定“它在哪里”。网络可以在训练中学习怎样组合它们。

如果选择拼接，输入会变成：

$$x_{\text{input}}=[x_{\text{token}};PE_{pos}]$$

这同样可行，但会改变维度，需要后续投影。加法更省参数，拼接则把两类特征在通道上分得更开。选择哪种方式，要看模型结构和训练目标，不是绝对对错。

但相加并不保证模型一定学到某种人类可解释的距离关系。位置编码只是提供结构，具体如何使用仍由训练决定。

## 为什么正弦和余弦可以表达位置平移

正弦和余弦成对出现后，可以利用和差公式：

$$\sin(a+b)=\sin a\cos b+\cos a\sin b$$

$$\cos(a+b)=\cos a\cos b-\sin a\sin b$$

因此，位置 $pos+k$ 的编码可以由位置 $pos$ 的编码经过线性变换得到。

这给网络提供了一种规律的坐标结构，而不是彼此无关的编号。不过，这种性质不等于网络自动学会相对位置，也不等于注意力分数会精确地只依赖距离。它提供的是可利用的数学结构。

## 可学习位置编码是不是更灵活

可学习位置编码会给每个位置一个可训练向量。它不需要手工指定频率，可以完全根据数据调整。

但灵活也意味着训练数据决定了位置表示。如果最大位置表长固定，超出部分就需要扩展、插值或其他策略。正弦编码则可以直接计算新位置，虽然可计算不等于模型一定泛化良好。

因此，比较两者时，不能只问“能不能表示位置”，还要问：

- 位置结构是否容易学习；
- 训练长度和推理长度是否一致；
- 模型是否需要相对位置；
- 新位置出现时如何处理；
- 位置特征会不会被后续层有效利用。

这些问题比“固定”或“可学习”两个标签更重要。

## 因果掩码已经包含顺序了吗

严格来说，因果掩码确实包含顺序信息。它规定当前位置只能读取哪些位置，因此并不是与位置无关。

所以，更准确的表述是：**没有位置编码、位置偏置、因果掩码等额外结构的裸自注意力，不能获得原始顺序。**

在实际的 decoder 中，即使暂时移除显式位置编码，因果掩码仍然提供了一种先后约束。这与“完全没有位置信息”的数学情形不同。

这个区分能帮助我们避免过度简化。位置可以来自显式向量，也可以来自掩码、相对偏置或其他结构。关键是模型最终是否获得顺序，而不是必须出现某一种名叫 PE 的模块。

## 位置信息会不会在深层被冲淡

位置编码加在输入上，后续还要经过多头注意力、前馈网络、残差连接和归一化。位置特征可能以复杂方式与内容混合。

这并不意味着它一定会消失。残差连接帮助信息跨层保留，训练也会让模型利用有用的位置特征。但“位置在输入里”与“每一层都能轻松读取相对位置”并不是同一件事。

后续出现相对位置偏置、RoPE 等方法，正是在尝试让位置更接近注意力关系本身。它们反映了不同的设计哲学：位置是输入的一种特征，还是 token 之间关系的一部分。

## 怎样做一个最小的位置消融实验

如果想亲手验证位置的作用，可以设计一个小实验，而不必训练完整大模型。

第一步，准备仅顺序不同的样本，并确保标签确实依赖顺序。例如，判断一个数字序列是否递增，或者判断主谓宾关系是否交换。

第二步，训练一个带位置编码的小模型，记录验证集表现。

第三步，在保持其他设置尽量一致的情况下移除位置编码，并考虑因果掩码等额外因素。比较性能、注意力权重和错误样本。

第四步，做输入重排测试。检查输出是否符合置换等变，并观察位置编码加入后输出如何变化。

这个实验的重点不是证明某个排行榜结论，而是建立一种可控直觉：当任务只依赖内容时，位置可能不重要；当任务依赖顺序时，缺少位置就会形成结构性限制。

实验还要避免数据泄漏。如果训练集里某个 token 总是对应某个答案，模型可能靠内容捷径完成任务，根本用不到顺序。因此，最好加入相同元素、不同排列的样本。

## 几个常见误解

**“注意力能看到所有 token，所以也知道它们的顺序。”** 看到全部内容不等于看到坐标。集合中的所有元素也同时可见，但集合没有顺序。

**“有因果掩码，就不需要讨论位置。”** 掩码提供了一种顺序约束，但显式位置和相对位置仍有不同的表达能力。需要把具体结构说清楚。

**“正弦位置编码就是为了让每个位置不同。”** 可区分只是最低要求。多频结构、平移规律和无参数生成同样重要。

**“加入位置后，模型就一定会计算相对距离。”** 模型有学习机会，不等于已经形成某种人类可解释算法。

**“RoPE 只是把正弦编码换个写法。”** 它把位置作用移到了 Query 和 Key 的旋转上，使相对位置直接进入点积，不只是改写输入公式。

## 位置编码之后，问题就结束了吗

并没有。正弦位置编码解决了“位置可以进入模型”的问题，但注意力内部怎样表达相对距离，仍然可以继续改进。

RoPE 就选择了另一条路径：不把位置仅仅加在输入上，而是旋转 Query 和 Key，让二者的点积直接包含相对位置。这也解释了为什么位置编码看似只是输入前的小步骤，实际上会影响整个模型的结构。

理解这一点后，再读 Transformer 的位置编码章节，就不会只把它当成一串需要背诵的三角函数。它真正解决的是一个很具体的问题：**把集合般的计算，重新变回有序列的计算。**

## 哪些任务更依赖位置

并不是所有输入都同样依赖顺序。图像分类、集合统计和某些特征匹配，可能更关心整体内容；语言理解、程序执行和时间序列预测，则通常离不开顺序。

即使在同一个任务里，不同子问题也可能不同。判断一句话是否提到“猫”，有时只凭词义就能完成；判断“谁追谁”，就必须利用结构。

这给模型评估一个提醒：如果测试数据大多可以通过内容关键词完成，即使去掉位置，分数也可能看起来不错。只有当样本专门区分排列、方向和依赖时，位置能力才会真正被检验。

因此，设计测试集时应该主动加入“同内容、不同顺序”的对照样本，而不是只看随机文本上的平均分。

## 位置和内容会怎样相互影响

位置加入输入后，注意力计算中的每个 Query 和 Key 都同时包含内容与位置。于是，一个 token 对另一个 token 的关注，不再只是“内容是否匹配”，也会受到“它们在哪里”的影响。

这很有用，但也让分析更复杂。某个注意力权重变大，可能来自语义匹配，也可能来自位置接近，或者二者共同作用。仅凭一张热力图，很难把原因完全分开。

如果想研究位置的作用，可以比较同一内容在不同位置的表现，或者把同一组 token 平移到序列其他区域。这样比随机看几个注意力图更能说明位置是否真的被使用。

RoPE 的相对位置推导之所以重要，也是因为它把这种关系写得更明确：内容和位置共同进入点积，而不是互相替代。

## 位置信息不只服务于自然语言

代码中的缩进、括号与执行顺序，都要求模型处理结构位置；多模态模型处理图像 patch 时，也需要知道空间坐标；音频和时间序列则关心时间轴上的相对间隔。

虽然这些输入形态不同，问题却很相似：如果模型把输入当成无序元素，就会丢失关键结构。

不过，不同模态需要的坐标未必是一维的。图像可能需要二维位置，视频还可能包含时间维。把文本中的一维位置方法直接照搬过去，有时需要额外调整。

所以，“位置”不只是第几个词，而是元素在结构中的坐标。理解这一点，能把位置编码从 Transformer 的一小节扩展成更一般的模型设计问题。

## 从是否需要位置，到需要怎样的位置

初学者最容易记住的是“Transformer 需要位置编码”。再往下走一步，就应该改成一组更具体的问题：任务依赖哪种顺序，现有结构提供了哪种位置，训练是否真的学会使用它。

正弦编码、可学习位置表、相对偏置和 RoPE，都是在回答这些问题。它们不是需要排队背诵的名词，而是不同信息入口和归纳偏置的选择。

当模型在某个顺序任务上失败时，也可以沿着这条线排查：数据是否真的需要顺序，模型是否获得位置，位置是否被训练目标充分利用，评估是否混入内容捷径。

## 为什么不直接把整数位置交给模型

最朴素的想法是给每个 token 一个整数：第 1 位是 1，第 2 位是 2。但一个连续增大的标量会把位置大小与特征大小混在一起，而且不同位置之间没有天然的周期和多尺度结构。

如果直接把整数作为一个特征，模型还需要学习怎样把数值大小转化为相邻、距离和方向。位置 100 的数值更大，并不意味着它应该在语义强度上比位置 10 大十倍。

正弦和余弦把整数映射成多组有规律的波形，可学习位置表则把整数映射成可训练向量。它们都在把简单的编号转换成更适合神经网络使用的表示。

这也说明，位置编码并不是因为有名字才复杂，而是因为“编号”与“可学习的结构特征”之间确实需要一次设计。

当然，整数位置仍然可以作为底层输入。RoPE 的角度计算同样从位置编号开始，只是随后通过频率和旋转把它变成更有结构的作用方式。

## 我会怎样复习这部分

先记住“猫追狗”和“狗追猫”的差别，再从 $\operatorname{Attention}(PX)=P\operatorname{Attention}(X)$ 看懂置换等变；接着区分位置编码、因果掩码和相对位置偏置；最后思考位置应该从输入进入，还是直接进入 token 之间的关系。

一旦这条线索建立起来，位置编码就不再是孤立的数学附件，而是理解 Transformer 结构的一把钥匙。
